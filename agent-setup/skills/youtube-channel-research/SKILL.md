# YouTube Channel Research

Build an auditable channel corpus instead of a single large transcript file.

## Workflow

1. Run `doctor` before the first project.
2. Run `init` to create a corpus, then place the user's prior knowledge, documents, claims, and research questions in `context.md`.
3. Put canonical channel tab URLs in `channels.txt`. Prefer `/videos`, `/shorts`, and `/streams` explicitly when all formats matter.
4. Run `ingest`. Keep acquisition metadata-first; do not download video unless captions are unavailable and the task requires local transcription.
5. Inspect `status`, transcript coverage, and a few normalized transcripts before inference.
6. Run `analyze-video` for per-video evidence extraction through direct OpenCode server calls to `google/gemini-3.1-pro-preview`.
7. Run `synthesize` only after the relevant per-video analyses exist.
8. Report coverage, failures, model used, and remaining blind spots.

Use the bundled CLI:

```bash
python3 scripts/channel_research.py doctor
python3 scripts/channel_research.py init ~/research/my-channel
python3 scripts/channel_research.py ingest ~/research/my-channel
python3 scripts/channel_research.py status ~/research/my-channel
python3 scripts/channel_research.py analyze-video ~/research/my-channel --concurrency 2
python3 scripts/channel_research.py synthesize ~/research/my-channel
```

## Evidence Rules

- Preserve the source URL, video ID, language, caption type, and timestamps.
- Treat autogenerated captions as noisy evidence. Flag uncertain names, numbers, and quotations.
- Distinguish transcript evidence, supplied context, model inference, and outside knowledge.
- Never turn an inference into a sourced claim.
- Cite channel claims with clickable YouTube timestamps.
- Preserve contradictions and uncertainty; do not optimize for a tidy narrative.
- Analyze videos independently before channel-level synthesis to reduce cross-video contamination.
- Keep raw acquisition artifacts immutable where practical. Regenerate derived Markdown instead of hand-editing it.

Read [references/evidence-contract.md](references/evidence-contract.md) when changing prompts, schemas, or report structure.

## Compute And Privacy

- Acquisition and transcript normalization run locally.
- OpenCode runs locally, but Gemini inference is remote. Send only files the user intends to analyze.
- Use direct model calls, one temporary OpenCode session per task, and delete sessions after completion.
- Default to concurrency `2` for Gemini 3.1 Pro. Raise it only after observing stable limits.
- Do not add comments, full media, OCR, or frame extraction by default. Add a lane only when it answers a defined research question.

## Missing Captions

Do not silently equate missing captions with missing content. Report those videos as coverage gaps. If the user asks for fuller coverage, use local audio transcription on the RTX 3060, then place the timestamped transcript in the existing video directory before analysis.

## Media Download Fallback

Prefer captions and metadata. Download audio/video only when the task needs prosody, body language, frame evidence, or local transcription.

If local `yt-dlp` can list formats but downloads fail with `HTTP Error 403`, `SABR`, `PO Token`, or client warnings, try the latest `yt-dlp` in a disposable runner and avoid the iOS client:

```bash
uvx --from yt-dlp yt-dlp --no-check-certificate \
  --extractor-args 'youtube:player_client=default,-ios' \
  -f 140 \
  -o 'audio.%(ext)s' \
  'https://www.youtube.com/watch?v=VIDEO_ID'
```

For a small playable video, format `18` is often the simplest combined 360p MP4:

```bash
uvx --from yt-dlp yt-dlp --no-check-certificate \
  --extractor-args 'youtube:player_client=default,-ios' \
  -f 18 \
  -o 'video.%(ext)s' \
  'https://www.youtube.com/watch?v=VIDEO_ID'
```

If `--no-check-certificate` is only needed because the `uvx` Python environment cannot find system CA certificates, say so in the receipt. Do not use browser automation as the first fallback for YouTube media; embedded playback may fail with player configuration errors even when `yt-dlp` succeeds.

## Update Runs

`ingest` uses a persistent archive and is safe to rerun for newly published videos. Do not delete the archive unless a complete recrawl is explicitly intended.
